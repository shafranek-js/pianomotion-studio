# Native TypeScript engine: проверка и ремонт, 2026-10-16

Рабочая папка: `C:\Projects\pianomotion-studio`. База до ремонта — `7edd431`, чистое дерево. Локальная версия исправлений — `0.1.0-dev.8`. Пользовательские изменения SF2/SF3 приняты как новая исходная точка; в этом цикле аудио не переделывалось. Commit/push/deploy не выполняются.

## Что действительно реализовано по внешнему плану

План `dual_engine_typescript_port_plan.md` из Antigravity изучен как описание намерений и прежних проверок. Пакет из 14 модулей, Native Worker, четыре команды и выбор движка существуют. Python остаётся вариантом по умолчанию. В браузере Native не требует инициализации Pyodide.

Статус «100% завершено» не подтверждался: пять тестов проверяли преимущественно форму API. Тест «matches golden assignments» сравнивал только число назначений. `@ts-nocheck` в больших перенесённых модулях не позволяет считать успешный typecheck доказательством численной корректности.

Настройка реально хранится в общем `app.settings` IndexedDB и совместимом `handthesia:settings`, а не в отдельном ключе `handthesia_calculation_engine`, указанном в плане. Сохранённые проекты перепланируются из исходных MIDI. Общий `engineVersion` Native пока объявляет совместимость с Python baseline, а не отдельный хеш исходников реализации; он сам по себе не доказывает эквивалентность. Отдельный Native source SHA включён в отчёт численного сравнения. Runtime handshake `engine-load` существует, но основная студия его отдельно не выполняет.

## Подтверждённые ошибки и исправления

| Дефект | Исправление и проверка |
|---|---|
| `_hand_avg` получил `null/null` вместо `-Infinity/Infinity` | Отрицательные времена pre-roll больше не исключаются. Пустое среднее раньше давало NaN, превращавшиеся в нулевые суставы и кости длиной более 20 дюймов. Восстановлены исходные bounds; тесты сверяют геометрию с Python. |
| Несколько независимых WeakMap ID одной ноты | MIDI loader, hand split, fingering, hands и API используют общий `figures.objId`. Иначе назначения, glissando и предпочтения рук терялись в зависимости от порядка обхода. |
| Replan использовал старую переменную `note` вместо `source_note` | Все поля редактируемой ноты теперь берутся из правильного объекта. До ремонта разные ID получали высоту последней ноты, что нарушало request-aware контракт. |
| Неизвестная рука принудительно становилась RIGHT до hand split | Отсутствие предпочтения сохраняется до разделения рук. Исправлены два неверных назначения в MIDI с темпом/педалями. |
| Первый pedal-off сравнивался с undefined | Начальное состояние педали считается отпущенным, как в Python. |
| Truncated MIDI принимался за корректный пустой | Проверяется длина meta/sysex/channel сообщений; повреждённый пример проходит существующий сценарий repair. |
| Callback прогресса затенял модульную переменную | Удалена локальная копия, подтверждено фактическое получение callback. |
| NaN округлялся в правдоподобный ноль | Численная граница API отклоняет non-finite результат, сохраняя ошибку вычисления вместо фиктивной геометрии. |
| Пустой kwargs не распознавался в build_hands | Конструктор получает явные options; default repair соответствует Python. |
| Инспектор показывал выбранный, а не рассчитавший проект движок | Active engine отслеживается по Worker, создавшему принятый результат; запрошенный выход показывается отдельно при несовпадении. |
| Экспорт выбирал движок из меняющихся глобальных настроек | Отдельный Worker получает calculationEngine из замороженного снимка. |
| Build ID не учитывал Native исходники | `packages/engine-ts/src`, package manifest и tsconfig включены в входы build hash. |

## Проверки и точные границы

- 488 unit-тестов / 43 файла, 31 Python-тест, typecheck, lint и production build проходят. Сборка сохраняет предупреждение о размере основного JS chunk.
- Все 13 MIDI fixtures и встроенный Chopsticks проходят request-aware analyze validation. Source identities и назначения пальцев/рук совпадают с эталонами на всех fixtures; stress-512 имеет 512 точных назначений и одинаковый результат до/после серии других входов.
- Replan проверяется настоящим request-aware validator, включая соответствие press pitch исходному note ID.
- Геометрия: все chain points первого tracked-right-hand pose сравниваются с Python golden с допуском 0.05 px; контрольные точки Chopsticks — 0.15 px. Эталоны не изменены.
- Независимый реальный Chrome Worker после ремонта: Chopsticks — 162 ноты, 71 начальная поза, максимальная кость пальца 2.2524 дюйма, нулевых костей нет. До ремонта были концы в [0,0,0] и растяжения более 20 дюймов.
- Browser lifecycle прошёл последовательно в Chrome/Edge через настоящий Worker: каталог, edit/replan, обе смены движка, Undo/Redo, seek за пределы первого окна, повторный импорт. Проверены 19 сегментов пальцев, wrist span и реальные sample-motion сообщения; 71 начальная и 49 поз после seek не имеют нарушений геометрии. Дополнительно 727 поз начальных окон 10 loaded fixtures не содержат растянутых/схлопнутых сегментов.
- Python Worker в Chrome: 15/15 проверок, включая все 13 неизменённых numerical goldens. [Протокол, результаты и неудачные попытки](evidence/native-engine-2026-10-16/VERIFICATION.md). Один промежуточный Edge-прогон остановился до вызова движка из-за `Failed to fetch` встроенного MIDI; причина не установлена, изолированный повтор прошёл.

## Численная эквивалентность: 100% ПОЛНЫЙ ПАРИТЕТ ДОСТИГНУТ

Команда `npm run test:native-parity` сохраняет `test-results/reports/native-parity.json` и проверяет строгий численный паритет без изменения допусков или эталонов.

После выравнивания кинематики:
- **Все 13 из 13 fixtures получили статус `PARITY PASS`** (0 различий во всех категориях, отчёт завершается `"passed": true`, exit code 0).
- **Release-time differences:** 0 (было 34 различия на 4 fixtures, полностью устранены).
- **Raw-pose coordinate differences:** 0 (было 7 367 различий компонентов, полностью устранены).

### Ключевые причины расхождений и их исправление:
1. **Дефолтные параметры кинематических функций в JS:** В Python `_splay_at(f, comp, stretch=1.0)` при отсутствии аргумента `stretch` использует полный предел разведения пальцев (1.0). В сгенерированном TypeScript аргумент имел значение по умолчанию `null`, из-за чего проверка `stretch < 1.0` в JS (`null < 1.0 === true`) ошибочно принимала значение комфортного разведения (0.418 rad вместо 0.959 rad), вызывая ложный штраф за растяжение в 61+ единиц и увод кисти в сторону. Аналогично исправлены параметры по умолчанию для `_clamp_tip`, `_clamp_prep`, `_key_spot`, `_solve_hand` и `_limit_tip` (`comp=0.0`, `stretch=1.0`, `low=1.0`).
2. **Коллизия переменной цикла в `_key_fix`:** Внешний цикл Гаусса-Ньютона использовал `for (_ = 0; _ < KEY_FIX_ITERS; _ += 1)`, а внутренний цикл линейного поиска шага — `for (_ = 0; _ < 6; _ += 1)`. В общем лексическом контексте функции внутренний цикл перезаписывал счетчик внешнего, приводя к преждевременному завершению итераций `_key_fix`. Замена на изолированные переменные `iter` и `stepIdx` восстановила точное совпадение сходимости с Python до 11 знаков после запятой.

## Продолжение и эксплуатация

Не сбрасывать данные сайта. После изменения движка дождаться завершения replan; при ошибке предыдущий проект и правки остаются доступны. Для контрольного результата выбрать Python в Diagnostics. Дальнейшие исправления Native должны проходить `test:native-parity` с неизменными goldens; снимок экспорта обязан сохранять выбранный runtime. Для browser regression использовать `playwright.worker.config.ts`, где Native suite включён отдельно от быстрых UI-тестов.
