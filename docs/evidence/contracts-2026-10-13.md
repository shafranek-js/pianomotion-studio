# W003 contract evidence — 2026-10-13

The implementation is in `packages/contracts`. Zod schemas cover `SongDocument`, notes and tracks, pianist profiles, fingering/performance/motion plans, project packages, engine requests/responses, resource descriptors, and cache keys. Context-aware refinements validate stable-ID uniqueness, optional many-source-to-one-normalized-note provenance, references, time/range/order constraints, package resource paths, plan revisions, profile revisions, and request/response artifact identity. Fingering dispositions explicitly distinguish playable, glissando, and unplayable notes; request validation enforces that performance events include the first two and omit the last.

Semantic unit cases are in `packages/contracts/test/contracts.test.ts`. They include duplicate IDs, valid same-pitch/same-time notes, missing tracks/notes/resources, non-finite and negative times, invalid event order and press/release pairs, unsupported schema versions and unknown fields, stale revisions, cache-key ranges, motion-frame validation (including equal default hand layers), cross-request plan identity, and malformed result note references. Request, song-context, and response checks enforce that fingering hands match normalized source notes, explicitly marked same-hand gliss runs (at least two notes, gaps no greater than 0.5 seconds) use the glissando disposition, and derived pedal switches exactly match the source controls after thresholding at 64 with unchanged states omitted. A solitary gliss mark remains playable, as do unmarked notes assigned to an engine-detected gliss run. The request-aware response helper checks returned fingering references/completeness and performance references/dispositions against the exact request inputs.

Source grounding: `midi_loader.py` (`Note`, `TrackInfo`, `MidiSong`, pedal conversion), `common.py` (`Performance`, `Transport.update`), `pianist.py` (`Pianist`), and `hands.py` (`HandAnimator.pose`, pose output, `ppi`, world-coordinate notes). See `../adr/ADR-001-contracts-and-time.md` for the accepted M0 boundary decisions and time/coordinate semantics.
