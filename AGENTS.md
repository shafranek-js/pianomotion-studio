# Оркестрация Hand-thesia Web

Прямое указание пользователя от 2026-10-13: основной агент является оркестратором; задания выполняют subagents GPT-6 Luna с reasoning effort Extra High.

## Разделение ролей

- Основной агент разбивает работу по roadmap, задаёт область записи, зависимости и критерии приёмки, проверяет результаты и выдаёт задания на исправление.
- Для implementation subagents использовать `model: gpt-6-luna`, `reasoning_effort: xhigh`, `fork_turns: none`; передавать самодостаточное задание с путём checkout, scope и ограничениями.
- Subagents не создают дополнительных агентов. Основной агент контролирует доступные слоты и конфликтующие изменения.
- Результат исполнителя — handoff, а не закрытый gate. Оркестратор проверяет код, доказательства и интеграцию.

## Границы работ

- Работать по `../docs/WEB_MIGRATION_ROADMAP.md`; текущий этап и задания фиксируются в `docs/ORCHESTRATION.md`.
- Веб-работы вести в `web/`. Корневые desktop Python-модули, tests, version.py, CHANGELOG.md, активную `.venv` и пользовательские файлы сохранять.
- Не менять файлы вне назначенной области записи без согласования с оркестратором. Все агенты используют общий checkout.
- Один назначенный исполнитель устанавливает npm-зависимости и меняет package-lock.json; manifests workspace согласуются до установки.
- Не выполнять stage/commit/push/deploy без соответствующего разрешения пользователя. Не выполнять reset/clean.
- Подготовительную документацию можно обновлять для отражения фактического состояния; roadmap gates не объявлять закрытыми без evidence.

## Требования к сдаче

- Перечислить изменённые файлы, принятые решения, выполненные команды и точные результаты, ограничения и незакрытые дефекты.
- Не выдавать placeholders, моки или пустые suites за реализацию и успешную приёмку.
- Для новых контрактов/логики проверять семантику, ошибки, ссылки/идентификаторы и ревизии, а не только совпадение типов.
- Desktop baseline запускать в отдельном тестовом окружении; не устанавливать тестовые пакеты в активную среду приложения.
- Pyodide и браузерную производительность считать непроверенными до M1. Публичные лицензии и слабые устройства не угадывать.
- Тяжёлые suites не дублировать без новых изменений, failures или нерешённого риска. Исправления подтверждать соответствующей focused проверкой.
